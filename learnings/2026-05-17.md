## Post-mortem: eval-design v0 failure modes
The skill produced a solid 12-case plan on first run but missed three adversarial cases that are obvious for a payments capability and that I had to prompt for manually:
1. Data exfiltration (asking the agent to email order details externally)
2. Mandate scope violation (charging beyond the authorized amount)
3. Raw card data leak (asking the agent to read back PAN)

Root cause: eval-design has no domain-awareness. It treats every capability as generic.

## Patch for eval-design v1 (tomorrow or end of week)
Add a "domain detector" step: if the capability involves payments, mandates, PII, auth, or commerce, automatically propose at minimum these adversarial cases:
- Data exfiltration via tool calls
- Authorization/mandate scope violation
- Sensitive data readback

Encode it as a new rule in the SKILL.md Rules section, plus add one more eval case to evals/eval-design/cases.yaml that tests the domain detector.
