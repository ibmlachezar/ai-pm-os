# Day 2 — Learnings

## What I shipped
- agent-architecture skill (.claude/skills/agent-architecture/SKILL.md)
- 5 eval cases (evals/agent-architecture/cases.yaml)
- 4 routing lines appended to CLAUDE.md
- Ran agent-architecture on the agentic checkout (auth → mandate validation → payment authorization → confirmation). Skill correctly asked diagnostics first, recognized the path is known and the p95 latency budget rules out agents, recommended a workflow. Also ran the trap case ("we want an AI agent for our data analysis tool") — skill pushed back on the word "agent" and forced diagnostics before recommending.

## What surprised me
- The skill produced a sharper recommendation than I would have on my own. I would have hand-waved past the latency math; the skill made it explicit (5-50 LLM calls in an agent loop cannot hit p95 <2.5s reliably).
- The pushback behavior worked on the trap case. The skill refused to recommend "agent" just because the user said "agent." That's the behavior I encoded yesterday in eval-design (refuse on vague terms); the same pattern carried over here.

## What this taught me about AI PM thinking
1. Default to the simplest architecture that could meet the requirements. Workflow before agent. Agent is a last resort, not a first choice.
2. Latency budget is a hard constraint that eliminates architectures, not a soft preference. State it upfront in any architecture discussion.
3. Eval shape changes with architecture: workflows need step-level evals, agents need trajectory evals. Hand off to eval-design accordingly.

## Compounding from Day 1
